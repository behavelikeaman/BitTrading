# BitTrading

BTC-USDT 무기한 선물 5분봉 단타를 위한 **의사결정 지원 시스템**.
주문을 대신 넣지 않는다. 진입 여부·수량·손절·청산가를 계산해 보여주고, 그 규칙이 과거에 실제로 돈이 됐는지 백테스트로 검증한다.

## 왜 만드는가

기존 매매 방식(50배, 증거금 대비 목표 10%, 손절 없이 물타기)에는 세 가지 구조적 문제가 있다.

| 문제 | 수치 |
|---|---|
| 목표가 수수료 대비 작다 | 목표 10% = 가격 0.28% 변동. 왕복 수수료가 수익의 29% |
| 청산이 손절 역할을 한다 | 50배 청산 거리 1.5%. 손익분기 승률 **88.8%** 요구 |
| "자본의 50%"는 리스크가 아니다 | 리스크 = 명목가 × 손절폭. 증거금 비율이 아니다 |
| 시장가 슬리피지가 안 세어진다 | 편도 0.02%만 되어도 필요 승률이 50.0% → 54.0% |

목표를 증거금 대비 순수익 25%(가격 0.58%)로 올리고 ATR 기반 손절을 두면 손익분기 승률이 **50.0%**로 내려간다.

| 순수익 목표 | 필요 가격변동 | 손익분기 승률 (손절 0.42%) |
|---|---|---|
| 10% | 0.28% | 71.4% |
| 20% | 0.48% | 55.6% |
| **25%** | **0.58%** | **50.0%** |
| 30% | 0.68% | 45.5% |

## 핵심 설계 원칙

1. **돈 계산은 전부 `src/lib/`의 순수 함수, 전부 TDD.**
2. **백테스트와 실시간은 같은 시그널·리스크 함수를 쓴다** (ADR-001).
3. **확정봉만 사용한다** — 리페인팅 금지 (ADR-006).
4. **백테스트는 수수료·슬리피지·펀딩·청산을 전부 반영한다** (ADR-007). 슬리피지는 추정하지 않고 실제 체결에서 측정한다 (ADR-014).
5. **포지션은 리스크 예산에서 역산한다** — 증거금 비율이 아니라 (ADR-009).
6. **v1은 알림 전용.** 주문 실행 코드 없음, 읽기 전용 API 키만 (ADR-002).

## Phase

| Phase | 내용 | 상태 |
|---|---|---|
| `0-core` | 지표·시그널·리스크·백테스트 엔진 + 대시보드·백테스트 화면 | 완료 |
| `1-paper` | 페이퍼 트레이딩 — 백테스트와의 정합성 검증 | 대기 |

### Phase 1이 답하는 질문

**"백테스트가 내린 판단을 실시간에서도 똑같이 내리는가?"** — 수익 여부가 아니다.

승률 50%와 55%를 구분하려면 400트레이드가 필요하다. 하루 5건이어도 80거래일이다. 한 달(약 100건) 관측의 승률 표준오차는 ±5.0%p라, 관측 승률 55%의 신뢰구간이 45~65%로 손익분기를 넘었는지조차 구분되지 않는다.

그래서 역할을 나눈다: **엣지는 백테스트가, 정합성은 페이퍼가** 담당한다 (ADR-020).

## 개발

Harness 프레임워크로 step 단위 실행한다.

```bash
python3 scripts/execute.py 0-core          # 순차 실행
python3 scripts/execute.py 1-paper         # 페이퍼 트레이딩 Phase
python3 scripts/execute.py 1-paper --push  # 실행 후 push
```

## 명령어

```bash
npm run dev            # 개발 서버
npm run build          # 프로덕션 빌드
npm run typecheck      # tsc --noEmit (build는 테스트 파일을 검사하지 않는다)
npm run lint           # ESLint
npm run test           # vitest
npm run fetch-history  # 과거 캔들 다운로드 (로컬 실행 전용)
npm run paper          # 페이퍼 트레이딩 티커 (Phase 1)
npm run divergence     # 페이퍼 vs 백테스트 괴리 검사 (Phase 1)
```

> 백테스트용 과거 데이터 다운로드와 실시간 조회는 거래소 도메인 접근이 필요하다. 네트워크가 제한된 CI/클라우드 환경에서는 차단될 수 있으므로 **로컬에서 실행**한다.

## 면책

이 소프트웨어는 매매 판단을 보조할 뿐 수익을 보장하지 않는다. 레버리지 거래는 원금 전액을 잃을 수 있다.
