# Architecture Decision Records — BitTrading

## 철학
실제 자본이 걸려 있다. 속도보다 **검증 가능성**이 우선이다.
단, 검증이 필요 없는 곳(UI·외부 API 래퍼)에는 오버엔지니어링하지 않는다.

---

### ADR-001: 백테스트와 실시간은 동일한 시그널·리스크 함수를 공유한다
**결정**: `src/lib/signal/`, `src/lib/risk/`를 백테스트 엔진과 실시간 API 라우트가 그대로 import 한다. 백테스트 전용 시그널 구현을 따로 만들지 않는다.
**이유**: "백테스트는 수익이 나는데 실전은 안 되는" 가장 흔한 원인은 전략 자체가 아니라 두 경로의 로직이 미세하게 다른 것이다. 함수를 하나만 두면 이 오류 종류가 구조적으로 불가능해진다.
**트레이드오프**: 시그널 함수가 실시간 컨텍스트(펀딩·호가)에 의존하지 못하고 캔들 배열만 받는 순수 함수여야 한다. 펀딩은 인자로 주입해 해결한다.

### ADR-002: v1은 알림 전용, 자동 주문 없음
**결정**: 주문 실행 코드를 작성하지 않는다. 거래·출금 권한이 있는 API 키를 요구하지 않는다. 시스템은 수량·손절·익절이 계산된 "주문 티켓"을 화면에 띄우고, 사용자가 거래소에서 직접 넣는다.
**이유**: 50배 레버리지에서 사이징·부호·반올림 버그 하나가 계좌를 지운다. 백테스트로 검증되지 않은 전략을 자동화하는 것은 손실을 자동화하는 것이다. 읽기 전용 키만 쓰면 코드 버그의 최대 피해가 "잘못된 화면"에 그친다.
**트레이드오프**: 진입이 수초 늦어진다. 5분봉 전략에서는 무시할 수 있다.
**재검토 조건**: 백테스트가 유의미한 기대값을 보이고 페이퍼 트레이딩 1개월을 통과한 뒤.

### ADR-003: 과거 데이터는 Binance, 실시간은 Deepcoin
**결정**: 백테스트용 5분봉은 Binance Futures 공개 klines 엔드포인트에서 받는다. 실시간 시세·펀딩과 실제 체결 기준은 Deepcoin을 쓴다.
**이유**: Binance는 수년치 5분봉을 무료·무인증으로 주고 유동성이 커 가격 기준이 안정적이다. 두 거래소의 BTC 무기한 가격 차이는 차익거래로 수렴하므로 전략 검증 목적에는 충분하다. 다만 실제 체결·청산·펀딩은 Deepcoin 기준이므로 실시간은 Deepcoin을 봐야 한다.
**트레이드오프**: 두 거래소 간 미세한 가격·펀딩 차이가 백테스트 오차로 남는다. 슬리피지 가정에 흡수시킨다.

### ADR-004: 외부 API는 라우트 핸들러에서만, 키는 서버 환경변수
**결정**: Deepcoin·Binance·Anthropic 호출은 전부 `src/app/api/` 안에서만 일어난다. 클라이언트는 자체 API만 호출한다.
**이유**: 거래소 키가 브라우저 번들에 들어가면 그대로 유출이다.
**트레이드오프**: 실시간성이 폴링 간격만큼 떨어진다. 5분봉에서는 무관하다.

### ADR-005: `src/lib/`는 전부 TDD, `services/`·`components/`·라우트는 빌드 검증
**결정**: 지표·시그널·사이징·래더·청산가·백테스트 엔진·메트릭은 테스트를 먼저 쓰고 통과시킨다. 외부 API 래퍼와 UI는 `npm run build` + 수동 검증으로 대체한다.
**이유**: 순수 함수는 입출력이 명확하고, 여기가 바로 돈이 틀리는 지점이다. 지표는 손계산 기대값으로 고정한다. 반대로 외부 API·UI는 목킹 비용이 크고 회귀 위험이 낮다.
**트레이드오프**: 라우트 조립 오류는 자동으로 잡히지 않는다. 수동 검증으로 감수한다.

### ADR-006: 확정봉만 사용한다
**결정**: `services/`는 진행 중인 캔들을 잘라내고 반환한다. 모든 지표·시그널은 확정된 캔들로만 계산한다.
**이유**: 미확정봉으로 판정하면 같은 5분 안에서 신호가 켜졌다 꺼지는 리페인팅이 일어난다. 백테스트는 확정봉으로 돌아가므로 실전과 괴리가 생기고, 사용자는 존재하지 않았던 신호에 진입하게 된다.
**트레이드오프**: 신호 확인이 최대 5분 늦다. 목표가 0.58% 변동이므로 감수 가능하며, 백테스트도 같은 지연을 반영하므로 성적이 정직해진다.

### ADR-007: 백테스트는 수수료·슬리피지·펀딩·청산을 전부 반영한다
**결정**: 진입·청산 각 0.04%(설정 가능) 수수료, 1틱 이상의 슬리피지, 8시간 주기 펀딩, 유지증거금률 기반 청산 판정을 엔진에 넣는다. 체결은 신호 캔들의 다음 캔들 시가부터 가능하다.
**이유**: 왕복 수수료 0.08%는 목표 0.58% 대비 14%다. 이를 빼고 돌린 백테스트는 전략을 실제보다 좋게 보이게 한다. 청산을 모델링하지 않으면 50배에서 이미 사라졌을 계좌가 백테스트에서는 살아남는다.
**트레이드오프**: 엔진이 복잡해지고 테스트가 늘어난다. 이 프로젝트의 존재 이유이므로 감수한다.

### ADR-008: 손절은 ATR 기반, 청산가를 손절로 쓰지 않는다
**결정**: 손절폭 = ATR(14) × 배수(기본 1.2). 청산가는 경고 표시용이며 손절 수단이 아니다. 계산된 청산가가 손절가보다 가까우면 진입을 차단한다.
**이유**: 청산을 손절로 쓰면 한 트레이드의 손실이 증거금 100%가 되어 손익분기 승률이 88.8%로 치솟는다. ATR 손절은 손실을 리스크 예산 안에 묶는다.
**트레이드오프**: 변동성 확대 구간에서 손절폭이 넓어져 수량이 줄고 수익 금액이 작아진다. 의도된 동작이다.

### ADR-009: 포지션 크기는 증거금 비율이 아니라 리스크 예산에서 역산한다
**결정**: 입력은 "자본금의 몇 %를 증거금으로"가 아니라 "이 트레이드에서 최대 얼마를 잃을 것인가"다. 확신 2%, 약간의 확신 1%를 기본값으로 하고, 명목가 = 리스크 예산 / (손절폭 + 수수료율)로 역산한다. 증거금은 결과값일 뿐이다.
**이유**: 증거금 비율은 리스크가 아니다. 동일 명목가라면 레버리지가 50배든 10배든 손익과 수수료가 같고 청산 거리만 달라진다. 명목가 20,000달러 기준 50배는 청산이 1.5%, 10배는 9.5%다. 즉 50배는 수익을 늘리지 않고 청산 확률만 올린다.
**트레이드오프**: 사용자 체감상 포지션이 작아 보인다. 대신 한 번의 역행으로 계좌가 사라지지 않는다.

### ADR-010: Claude는 해설자이지 판단 주체가 아니다
**결정**: 진입·청산·사이징 결정은 전부 `src/lib/`의 결정론적 함수가 내린다. Claude는 현재 레짐 설명과 매매 후 저널 작성에만 쓴다. 모델은 `claude-opus-5`, 요청당 1회 호출, `effort: 'low'`(단순 요약 작업).
**이유**: LLM 출력은 재현되지 않으므로 백테스트할 수 없다. 백테스트할 수 없는 규칙에 자본을 걸 수 없다.
**트레이드오프**: 뉴스·정성 정보를 자동 반영하지 못한다. 사용자가 무효 필터를 수동으로 켜서 대응한다.

### ADR-011: 외부 API 호출에 자체 래퍼 계층을 만들지 않는다
**결정**: Binance·Deepcoin은 `fetch`로 직접 호출하고, Claude는 `@anthropic-ai/sdk`를 그대로 쓴다.
**이유**: 호출 지점이 소수라 추상화 이득이 없다.
**트레이드오프**: 호출부가 약간 반복된다. 읽기 쉬움을 우선한다.

### ADR-012: 수수료율과 유지증거금률은 거래소에서 읽는다
**결정**: `feeRatePerSide`와 `maintenanceMarginRate`를 상수로 두되 기본값은 **추정치임을 명시**하고, Deepcoin의 `GET /deepcoin/account/trade-fee`(실제 내 수수료율)와 `GET /deepcoin/market/step-margin`(유지증거금 구간표)에서 읽은 값으로 덮어쓴다. 대시보드는 현재 적용 중인 값이 실측인지 기본값인지 표시한다.
**이유**: 이 두 값은 목표 가격폭·청산가·손익분기 승률을 직접 결정한다. 편도 수수료가 0.04%인지 0.06%인지에 따라 손익분기 승률이 50.0%와 54.0%로 갈리고, 유지증거금률은 청산가를 좌우한다. 계좌 등급·거래량에 따라 수수료가 달라지고 유지증거금은 포지션 크기 구간별로 달라지므로, 상수로 박으면 실제와 어긋난 숫자를 보고 주문하게 된다.
**트레이드오프**: 읽기 전용 API 키가 있어야 실측값을 쓸 수 있다. 키가 없으면 기본값으로 동작하되 화면에 "추정치" 표시를 띄운다.

### ADR-013: 목표는 증거금 대비 %가 아니라 손절폭의 배수(R)로 정의한다
**결정**: 전략의 목표는 `targetRMultiple`(손절폭 대비 배수)로 정의한다. 기본값 1.38. "증거금 대비 순수익 %"는 현재 레버리지 기준으로 **환산해서 보여주기만** 한다.
**이유**: "증거금 대비 25%"는 레버리지에 종속된 값이다. 50배에서는 가격 0.58% 변동이지만 25배에서는 1.08%, 10배에서는 2.58%다. 같은 이름의 목표가 레버리지를 바꾸는 순간 완전히 다른 전략(훨씬 드물게 도달하고 훨씬 오래 보유하는)이 되어버린다. 손절폭 배수로 정의하면 레버리지와 무관하게 전략이 고정되고, 레버리지는 원래 역할인 청산 거리에만 영향을 준다.
**트레이드오프**: 사용자가 익숙한 "몇 %" 감각과 한 단계 떨어진다. 화면에 두 표기를 나란히 띄워 해결한다.
**기준 환산 (50배, 편도 수수료 0.04%, 손절 = ATR 1.2배 = 0.42%)**: `targetRMultiple` 1.38 → 가격 0.58% → 증거금 대비 순수익 25% → 손익분기 승률 50.0%.

### ADR-014: 체결 비용은 수수료 + 슬리피지이며, 슬리피지는 실제 체결에서 측정한다
**결정**: 사용자는 **시장가(테이커)로 매매**한다. 따라서 체결 비용은 수수료만이 아니라 `수수료 + 슬리피지`다. 슬리피지 기본값은 편도 0.02%로 두되 **추정치임을 명시**하고, Deepcoin `GET /deepcoin/trade/fills`(읽기 전용)에서 실제 체결가를 받아 의도 가격과 비교해 **실측 슬리피지를 계산**한 뒤 백테스트·계산기의 기본값을 덮어쓴다.
**이유**: 편도 수수료 0.04%는 확정값이지만 슬리피지는 호가 깊이·주문 크기·변동성에 따라 달라지고, 50배에서는 증거금 대비 비용으로 증폭된다. 목표 0.58%·손절 0.42% 기준으로 편도 슬리피지가 0.02%만 되어도 손익분기 승률이 50.0%에서 54.0%로 **4%p** 오른다. 0.05%면 60.0%가 되어 전략이 성립하지 않는다. 이 값을 추정한 채로 백테스트를 돌리면 결과가 통째로 무의미하다.
**트레이드오프**: 실측에는 읽기 전용 키와 과거 체결 이력이 필요하다. 이력이 없으면 기본값으로 동작하되 화면과 백테스트 리포트에 "슬리피지 추정치" 경고를 띄운다.

| 편도 슬리피지 | 왕복 총마찰 | 증거금 대비(50배) | 손익분기 승률 |
|---|---|---|---|
| 0.00% (수수료만) | 0.08% | 4.0% | 50.0% |
| **0.02% (기본 가정)** | **0.12%** | **6.0%** | **54.0%** |
| 0.03% | 0.14% | 7.0% | 56.0% |
| 0.05% | 0.18% | 9.0% | 60.0% |

### ADR-015: 백테스트는 시장가 진입과 지정가 진입을 모두 모델링해 비교한다
**결정**: `BacktestParams.entryType`을 `'market' | 'limit'`으로 두고 둘 다 돌려 비교할 수 있게 한다.
- `'market'`: 신호 다음 캔들 시가에 무조건 체결. 테이커 수수료 + 슬리피지 적용. 체결률 100%.
- `'limit'`: 신호 캔들 종가에 지정가를 걸고 `limitValidBars` 안에 가격이 닿아야 체결. 메이커 수수료, 슬리피지 0. 닿지 않으면 **트레이드 자체가 없다.**

**이유**: 시장가에서 지정가로 바꾸면 왕복 마찰이 0.12%에서 0.04%로 떨어져 손익분기 승률이 54.0% → 46.0%, **8%p** 개선된다. 그러나 돌파 추종 전략에서 지정가는 되돌림을 기다리는 것이라 **가장 강하게 달아난 트레이드(= 큰 승자)를 놓치는 역선택**이 발생한다. 이 둘 중 어느 쪽이 순이익이 큰지는 이론으로 알 수 없고 **백테스트로만 답할 수 있다.** 답을 모르는 채 한쪽을 고르는 것이 이 프로젝트가 막으려는 문제다.
**트레이드오프**: 엔진에 미체결 경로가 추가되어 복잡해진다. 체결률(`fillRate`)을 리포트에 노출해 역선택 크기를 눈으로 확인하게 한다.

## Phase 1 — 페이퍼 트레이딩

### ADR-016: 체결 상태 기계를 백테스트와 페이퍼가 공유한다
**결정**: 현재 `runBacktest` 루프 안에 박혀 있는 체결·청산 판정(펀딩 부과, 대기 주문 체결, 물타기 레그 체결, 손절·청산·익절·타임아웃 판정)을 `src/lib/execution/`의 순수 상태 기계로 추출한다. 백테스트는 과거 캔들을 순회하며 이 함수를 호출하고, 페이퍼 트레이더는 새 확정봉이 나올 때마다 같은 함수를 한 번 호출한다.
**이유**: ADR-001의 연장이다. 페이퍼 트레이딩이 자체 체결 로직을 가지면 "백테스트와 페이퍼가 다른 결과를 내는데 어느 쪽이 맞는지 모르는" 상태가 된다. 그러면 페이퍼는 아무것도 검증하지 못한다. 함수를 하나만 두면 두 경로가 어긋나는 것이 구조적으로 불가능해진다.
**트레이드오프**: 기존 백테스트 엔진을 리팩터링해야 하고, 그 과정에서 회귀가 날 수 있다. 기존 테스트 196개가 전부 통과하는 것으로 등가성을 담보한다.

### ADR-017: 페이퍼 상태는 원자적 JSON 파일에 저장한다
**결정**: 열린 포지션과 매매 일지를 `data/paper-state.json`, `data/paper-journal.jsonl`에 저장한다. DB를 쓰지 않는다. 쓰기는 임시 파일에 쓴 뒤 rename 하는 원자적 방식으로 한다.
**이유**: 사용자 1인이 로컬에서 돌리는 도구이고 동시 쓰기가 없다. DB는 운영 부담만 늘린다. 다만 티커가 5분마다 상태를 덮어쓰므로, 쓰는 도중 프로세스가 죽으면 파일이 깨져 열린 포지션을 통째로 잃는다. rename은 원자적이라 이를 막는다.
**트레이드오프**: 여러 기기에서 동시에 돌릴 수 없다. 단일 사용자 도구이므로 수용한다.

### ADR-018: 티커는 웹 라우트가 아니라 별도 CLI 프로세스다
**결정**: 페이퍼 트레이딩의 시간을 진행시키는 주체는 `npm run paper`로 띄우는 장기 실행 CLI다. 웹 라우트나 브라우저가 상태를 진행시키지 않는다. UI는 상태 파일을 읽기만 한다.
**이유**: 브라우저가 진행시키면 탭을 닫는 순간 포지션이 멈춘다. 5분봉 전략에서 그것은 손절을 놓친다는 뜻이다. 라우트는 요청이 와야 실행되므로 마찬가지다. 실제로 24시간 돌아야 하는 것은 프로세스지 화면이 아니다.
**트레이드오프**: 사용자가 터미널을 하나 더 띄워야 한다. 대신 화면을 꺼도 기록이 이어진다.

### ADR-019: 페이퍼 트레이딩은 슬리피지를 모델링하지 않는다 — 결과는 상한선이다
**결정**: 페이퍼 체결가는 백테스트와 같은 규칙(시장가는 다음 캔들 시가, 지정가는 지정가)으로 정하되, 실제 호가를 모르므로 슬리피지는 설정값을 그대로 적용한다. 화면과 리포트에 "슬리피지는 가정값이며 실거래는 이보다 나쁘다"를 항상 표시한다.
**이유**: 페이퍼는 주문을 넣지 않으므로 진짜 체결가를 알 수 없다. 이를 숨기면 사용자가 페이퍼 성적을 실거래 기대치로 착각한다. 왕복 마찰 0.02%p 차이가 필요 승률 2%p를 움직이는 구조에서 이 착각은 비싸다.
**트레이드오프**: 페이퍼가 실거래를 완전히 재현하지 못한다. 그 격차를 숨기지 않고 명시하는 것으로 대신한다.

### ADR-020: 페이퍼의 역할은 엣지 측정이 아니라 배선 검증이다
**결정**: 페이퍼 트레이딩의 1차 산출물은 "수익이 났는가"가 아니라 **"백테스트와 같은 판단을 내렸는가"**다. 페이퍼가 기록한 각 신호에 대해 같은 구간을 백테스트로 재생해 진입 시각·방향·확신도·체결가가 일치하는지 대조하고, 불일치를 리포트한다.
**이유**: 표본이 부족해 엣지를 측정할 수 없다. 승률 50%와 55%를 2 표준오차로 구분하려면 400트레이드가 필요한데, 하루 5건이어도 80거래일이 걸린다. 한 달(약 100건) 관측 시 승률 표준오차는 ±5%p라, 관측 승률 55%의 신뢰구간이 45~65%로 손익분기 54%를 넘었는지조차 알 수 없다.
반면 배선 오류는 표본 몇 건으로도 드러난다. 실시간 피드의 캔들 경계, 미확정봉 처리, 지표 워밍업, 상태 복원 같은 것들은 백테스트가 구조적으로 잡을 수 없고 페이퍼만 잡을 수 있다.
**트레이드오프**: "페이퍼에서 돈이 벌렸으니 실거래해도 된다"는 결론을 낼 수 없다. 그 판단은 백테스트 표본이 담당한다.

### ADR-021: 페이퍼 모듈은 주문 실행 경로를 갖지 않는다
**결정**: `src/lib/execution/`과 페이퍼 러너는 거래소 주문 API를 import 하지 않는다. 체결은 전부 시뮬레이션이며, 실거래 연동은 이 Phase의 범위가 아니다.
**이유**: 페이퍼 트레이딩은 자동매매로 가는 가장 자연스러운 경로다. "이미 체결 로직이 있으니 주문만 붙이면 된다"는 유혹이 생긴다. 그러나 ADR-002의 근거(검증되지 않은 전략의 자동화는 손실의 자동화다)는 그대로 유효하다. 모듈 경계에서 차단해 실수로도 그 선을 넘지 않게 한다.
**트레이드오프**: 나중에 실거래를 붙일 때 어댑터를 따로 만들어야 한다. 의도된 마찰이다.

### ADR-022: 교차는 이평선 배열·이격과 함께 읽는다 — 셋업별로 채점한다
**결정**: EMA12 × BB중앙선 교차를 단독 트리거로 쓰지 않고, SMMA 스택(20·55·95·135)의 배열과 이격 상태를 함께 읽어 셋업으로 분류한다. 채점 항목의 통과 조건은 셋업마다 다르다.

| 배열 | 교차 | 이격 | 셋업 | 방향 |
|---|---|---|---|---|
| 정배열 | 상향 | 정상 | 눌림목 재진입 | 롱 |
| 정배열 | 상향 | 과대 | 과이격 추격 | **진입 금지** |
| 정배열 | 하향 | 과대 | 과이격 되돌림 | 숏 (목표: 스택 하단) |
| 정배열 | 하향 | 정상 | 판단 보류 | 없음 |
| 역배열 | — | — | 위의 거울상 | — |
| 혼조 | 상향/하향 | — | 밴드 돌파 | 교차 방향 |

**이유**: 사용자의 실전 기록에서 나온 두 자리(정배열 과이격 후 되돌림 숏, 정배열 눌림목 재진입 롱)가 기존 8항목 체크리스트에서 **구조적으로 만점이 불가능했다.** `higherTimeframe`은 진입 방향과 상위 추세의 일치를 요구해 정배열 숏을 무조건 감점했고, `bbPosition`은 밴드 바깥 종가를 요구해 중앙선 되돌림 계열을 전부 감점했다. 즉 기존 채점은 "밴드 돌파 + 추세 순방향" 한 가지 셋업만 잴 수 있었고, 실제로 수익이 난 자리는 낮은 점수를 받았다. 하나의 조건표로 성격이 다른 자리를 재는 것이 원인이다.

되돌림 셋업에서 상위 프레임 기준을 뒤집은 것도 같은 이유다. 되돌림은 상위 추세가 살아 있어야 스택 하단에서 멈출 근거가 생긴다. 상위 추세까지 꺾였다면 그것은 되돌림이 아니라 추세 전환이고, 목표가 지지받는다는 전제가 사라진다.

**이격을 ATR이 아니라 가격 대비로 재는 이유**: ATR로 정규화하면 급등 구간에서 ATR도 함께 커져 **간격이 벌어질수록 비율이 오히려 줄어드는 역전**이 생긴다. 실제로 ATR 기준으로 구현했을 때 급등 구간의 이격 비율이 조용한 구간보다 낮게 나왔다. 화면에서 눈으로 보는 "선 간격"은 가격 대비 비율이다. 절대 기준 대신 최근 100봉 중앙값의 배수로 판정해 레짐마다 다른 평소 이격을 흡수한다.

**트레이드오프**:
- 채점 항목이 8개에서 10개로 늘어 확신 임계값을 6/8에서 7/10으로 옮겼다. 이전 점수와 직접 비교할 수 없다.
- SMMA135 워밍업 때문에 **135봉 이상이 있어야 진입 판정이 나온다.** 백테스트·페이퍼 모두 앞부분 135봉은 신호가 나지 않는다.
- 과이격 판정 기본값(최근 중앙값의 1.8배, 하한 0.15%)은 **검증되지 않은 추정치다.** 이 값이 과이격 되돌림 셋업의 빈도를 직접 좌우하므로 실데이터 백테스트로 보정해야 한다.
- 셋업별 성적을 따로 재기 위해 트레이드에 셋업을 기록한다. 전체 평균만 보면 성격이 다른 자리가 서로의 성적을 가린다.
