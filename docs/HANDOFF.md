## 0. 지금 당장 할 일 (2026-09-13 세션에서 이어짐)

**실데이터 백테스트를 처음 돌렸고, 전략이 전 구간에서 손실이었다. 그런데 그보다
중요한 것은 화면의 손익분기 승률이 틀렸다는 사실이다.**

### 6개월 백테스트 결과 (2026-06-01 ~ 09-12, 5분봉, 50배, 자본 5,000)

| 목표 R | 트레이드 | 승률 | 화면이 말한 손익분기 | PF | 기대값/건 | 순손익 | MDD |
|---|---|---|---|---|---|---|---|
| 1.38 | 612 | 46.24% | 54.02% | 0.37 | −8.02 | −4,907 | 98.1% |
| 3 | 515 | 33.59% | 32.14% | 0.54 | −9.39 | −4,834 | 97.2% |
| 5 | 460 | 28.48% | 21.43% | 0.65 | −10.24 | −4,708 | 95.8% |
| 7 | 448 | 28.35% | 16.07% | 0.69 | −10.24 | −4,587 | 94.1% |

셋업별 (R=1.38): 눌림목 363건 43.5% / 과이격 되돌림 145건 47.6% / 밴드돌파 104건
53.9% — **전부 기대값 음수이고 셋업 간 차이가 작다.** 사용자의 경험칙은 이 데이터에서
아직 검증되지 않았다.

### 가장 중요한 발견: 손익분기 승률이 15~20%p 낙관적이다

R=3·5·7에서 화면은 "손익분기를 넘겼다"고 초록불을 켰는데 계좌는 97% 녹았다.
PF와 승률에서 평균 승/패를 역산하면:

| 목표 R | 화면이 말한 필요 승률 | 실제로 필요했던 승률 | 이론 손익비 | **실제 손익비** |
|---|---|---|---|---|
| 1.38 | 54.02% | ~70% | 1.38 | **0.43** |
| 3 | 32.14% | ~48% | 3 | **1.07** |
| 5 | 21.43% | ~41% | 5 | **1.42** |
| 7 | 16.07% | ~36.5% | 7 | **1.74** |

**실제 손익비가 이론의 25~30%밖에 안 된다.** 이 숫자를 믿고 매매 여부를 판단하면
그대로 계좌가 녹는다. 다른 무엇보다 이것부터 고쳐야 한다.

### 원인 가설: 물타기(ladder)의 비대칭

평균 손실이 R=1.38에서 23.5, R=7에서 46.9로 **2배가 됐다.** 손절폭은 ATR×1.2로
같은데도 그렇다. R이 크면 보유가 길어지고 물타기 레그가 체결될 기회가 늘어난다.

- 이기는 거래: 1차 진입만 체결된 채 익절 → **1배로 번다**
- 지는 거래: 물타기까지 전량 체결된 뒤 손절 → **2배로 잃는다**

`planPosition`의 `breakEvenWinRate`는 riskBudget·rewardAtTarget 둘 다 **전량 체결**을
가정한다. 실제 체결 분포를 모르므로 이 비대칭이 계산에서 빠진다.

### 다음 작업 (합의된 순서)

1. **백테스트에 물타기 on/off 옵션 추가** — 레그 1개로 돌려 가설을 검증한다.
   물타기가 원인이면 실제 손익비가 이론치에 근접해야 한다.
2. **리포트에 실측 손익비 기반 필요 승률 추가** — `1 / (1 + 평균승/평균패)`.
   이론값과 나란히 놓으면 괴리가 한눈에 보인다. 이게 진짜 숫자다.
3. 두 값이 일치하는지 확인한 뒤에야 전략 개선(목표·손절·셋업 임계값)을 논할 수 있다.

**주의**: 서킷브레이커로 8,094~10,160봉(전체의 27~34%)이 막혔다. 나머지 구간만
검증된 결과다. 한도를 늘려 재실행하는 것도 검토할 것.

## 1. 이 프로젝트가 존재하는 이유

사용자는 딥코인 BTC-USDT 무기한 선물 **5분봉 스캘퍼**다. 기존 매매 방식에 세 가지 구조적 문제가 있었고, 이 도구는 그것을 숫자로 드러내고 검증하기 위해 만들어졌다.

| 문제 | 수치 |
|---|---|
| 목표가 마찰 대비 작다 | 증거금 대비 10% 목표 = 가격 0.28% 변동. 왕복 수수료가 수익의 29% |
| 청산이 손절 역할을 했다 | 50배 청산 거리 1.5%. 손익분기 승률 **88.8%** 요구 |
| "자본의 50%"는 리스크가 아니다 | 리스크 = 명목가 × 손절폭이지 증거금 비율이 아니다 |

**해결**: 목표를 손절폭의 1.38배(R배수)로 재정의하고 ATR 손절을 도입해 손익분기 승률을 **50%대**로 내렸다.

## 2. 반드시 알아야 할 도메인 수치

사용자 실제 조건: **시장가(테이커) 매매**, 편도 수수료 0.04%, 50배 → 왕복 4%(증거금 대비).

### 핵심 공식
```
손익분기 승률 = (손절폭 + 왕복마찰) / (목표폭 + 손절폭)
```

### 체결 비용 민감도 (손절 0.42%, 목표 1.38R = 0.5796%)

| 왕복 총마찰(명목가) | 증거금 대비(50배) | 손익분기 승률 |
|---|---|---|
| 0.04% | 2.0% | 46.0% |
| 0.08% (수수료만) | 4.0% | 50.0% |
| **0.12% (기본 가정)** | **6.0%** | **54.0%** |
| 0.18% | 9.0% | 60.0% |

**수수료와 슬리피지는 왕복 총마찰로 완전히 동일하게 작용한다.** 편도 수수료 0.06%와 (수수료 0.04% + 슬리피지 0.02%)는 둘 다 54.0%다. 0.02%p마다 필요 승률이 약 2%p 오른다.

### 레버리지의 진실
동일 명목가라면 레버리지는 손익과 수수료를 바꾸지 않고 **청산 거리만** 바꾼다. 명목가 $20,000 기준 50배는 청산 1.5%, 10배는 9.5%. 테스트로 고정돼 있다(`sizing.test.ts` — 레버리지 독립성).

### 표본 수 현실
승률 50%와 55%를 2 표준오차로 구분하려면 **400트레이드**. 하루 5건이어도 80거래일. 한 달(100건) 관측의 승률 표준오차는 ±5.0%p라 55%의 신뢰구간이 45~65%다. → **페이퍼 트레이딩으로는 엣지를 측정할 수 없다.**

## 4. 설계의 핵심 (ADR 22건 중 반드시 지킬 것)

- **ADR-001 / ADR-016**: 백테스트·실시간·페이퍼가 **동일한 시그널·리스크·체결 함수**를 쓴다. `src/lib/execution/machine.ts`의 `stepExecution`이 체결 판정의 유일한 구현이다. 재구현 금지.
- **ADR-006**: 확정봉만 사용. 미확정봉 판정은 리페인팅을 낳는다.
- **ADR-002 / ADR-021**: **주문 실행 코드 없음.** `src/lib/execution/`은 `src/services/`를 import 하지 않는다. 페이퍼는 자동매매로 가는 자연스러운 경로라 모듈 경계에서 차단했다.
- **ADR-008**: 손절은 ATR 기반. 청산가를 손절로 쓰지 않는다.
- **ADR-009**: 포지션은 **리스크 예산 → 명목가 → 수량 → 증거금** 순서로 역산. 증거금 비율에서 출발 금지.
- **ADR-013**: 목표는 R배수(`targetRMultiple`)로 정의. 증거금 대비 %는 환산 표기일 뿐 — 레버리지 종속값이라 그것으로 정의하면 레버리지를 바꿀 때 전략이 통째로 달라진다.
- **ADR-022**: 교차는 단독으로 읽지 않는다. **SMMA 스택(20·55·95·135)의 배열 + 이격**과 함께 읽어 셋업을 분류하고, 셋업마다 다른 조건으로 채점한다. 사용자의 실전 셋업 두 가지(정배열 과이격 되돌림 숏, 정배열 눌림목 롱)가 기존 채점에서 구조적으로 감점되던 것을 고친 결정이다. **이격은 ATR이 아니라 가격 대비로 잰다** — ATR 정규화는 급등할수록 비율이 줄어드는 역전을 만든다.
- **ADR-019 / ADR-020**: 페이퍼 성적은 **상한선**이다. 슬리피지 경고는 접을 수 없고, 승률은 반드시 신뢰구간과 함께 표시한다.

## 5. 개발 중 실제로 잡은 버그 (재발 방지)

1. **`Infinity`는 JSON에서 `null`이 된다** — `profitFactor`가 화면에 "—"로 떴다. 타입을 `number | null`로 바꾸고 JSON 왕복 테스트를 고정했다.
2. **캔들 진입 시점에 청산가를 한 번만 계산** — 같은 캔들에서 물타기 레그가 체결되면 평단·청산가가 내려가는데 반영 못 했다. 레그 체결마다 재계산하도록 수정.
3. **`npm run build`가 테스트 파일을 타입체크하지 않는다** — `npm run typecheck`를 추가했다. AC에 반드시 포함할 것.
4. **얕은 병합으로 기본값이 날아감** — 백테스트 라우트에서 `account`·`entry`를 각각 따로 병합하도록 수정.
5. **Stop hook의 `npm run build`가 개발 서버를 죽였다** — 프로덕션 빌드가
   dev 서버의 `.next`를 덮어써 `__webpack_modules__[moduleId] is not a function`
   으로 Internal Server Error가 났다. `next.config.ts`의 `distDir`을
   `NEXT_DIST_DIR` 환경변수로 분리하고, 검증 빌드는 `.next-verify`에 쓰도록
   고쳤다. **개발 서버를 켜둔 채 `npm run build`를 같은 디렉토리에 돌리지 마라.**
6. **step 정의의 모델 ID가 구세대였다** — `claude-sonnet-4-6` → `claude-opus-5`. LLM 관련 작업은 `claude-api` 스킬을 먼저 읽을 것.

7. **청산가가 손절가보다 가까운데 주문 티켓이 그대로 노출됐다** — ADR-008은
   "진입을 차단한다"인데 step 파일이 경고만 지시해 구현이 경고에 그쳤다.
   그 상태에서는 손절이 체결되지 않아 화면의 손실 수치가 실제와 다르다.
   `PositionPlan.tradable`을 추가해 차단한다.
8. **차트가 `fitContent()` 미호출로 오른쪽에만 몰렸고**, 최신 마커가 오른쪽
   끝에서 잘렸다. `rightOffset`으로 여백을 뒀다.
9. **`Infinity`는 JSON에서 `null`이 된다** — `profitFactor`가 화면에 "—"로 떴다.
   타입을 `number | null`로 바꾸고 JSON 왕복 테스트를 고정했다.

### 테스트 픽스처 주의
합성 캔들은 `open`이 항상 이전 `close`라 **지정가가 100% 체결되고 손절·청산·물타기 경로를 밟지 않는다.** 각 경로 검증에는 `scenario()` 픽스처(진입 이후 캔들을 직접 지정)를 쓴다.

## 6. 이 환경(클라우드 세션)의 제약

- **거래소 도메인이 egress 차단**된다 (`api.deepcoin.com`, `fapi.binance.com` → 403). 실제 데이터 수집·페이퍼 트레이딩은 **사용자 로컬에서만** 가능하다.
- **`scripts/execute.py`(harness 러너)를 이 세션에서 실행할 수 없다.** 중첩 에이전트 생성이 금지돼 있다(권한 모드와 무관). 사용자 로컬에서는 동작한다 — root 환경 대응으로 `--permission-mode auto`로 이미 수정해뒀다.
- 따라서 이 세션에서는 **step 파일을 직접 읽고 순서대로 구현**하는 방식으로 진행했다.

## 7. 사용자 환경 메모

- 딥코인 읽기 전용 키는 **연결돼 있다.** `.env.local`에 3개 값이 들어 있다.
- **`.env.local` 값에 `$`가 있으면 반드시 역슬래시로 escape 하라.** Next.js가
  환경변수로 치환해 `$` 앞부분만 남긴다. 따옴표로는 못 막고 역슬래시만 통한다.
  실제로 이것 때문에 패스프레이즈가 8자로 잘려 전송됐다.
- 과거 데이터는 사용자 로컬 `data/`에 6개월치(2026-06-01~09-12)가 받아져 있다.
- 백테스트·페이퍼·데이터 수집은 **전부 사용자 로컬에서만** 가능하다 (6번 참조).

```bash
npm run fetch-history -- --from YYYY-MM-DD --to YYYY-MM-DD
npm run dev     # localhost:3000/backtest
```

## 8. 아직 확정되지 않은 것

- **전략의 실효성 자체** — 6개월 백테스트에서 모든 설정이 손실이었다. 위 0번 항목 참조. 물타기 비대칭을 규명하기 전까지는 어떤 파라미터 조정도 의미가 없다.
- **사용자의 실제 슬리피지** — 읽기 전용 API 키는 연결됐지만 슬리피지는 **최근 300봉(약 25시간) 안의 체결**이 있어야 실측된다. 그 전까지는 추정 0.02%다. 왜 아직 추정인지는 대시보드 배지가 설명한다.
- **Deepcoin 실제 수수료율** — ✅ **실측 완료: 테이커 0.04%/편도.** 추정 기본값과 일치했다. 왕복 수수료 0.08%는 확정값으로 봐도 된다.
- **유지증거금률** — `step-margin`(공개 엔드포인트)으로 읽는다. 아직 미확인.
- **백테스트 결과 자체** — 아직 실제 시장 데이터로 돌려본 적이 없다. 이 환경에서 네트워크가 막혀 있어 합성 데이터로 파이프라인만 검증했다.
- **과이격 판정 임계값** (`extendedMedianMultiple` 1.8, `extendedMinPct` 0.15%) — 순수한 추정치다. 이 두 값이 "과이격 되돌림" 셋업이 얼마나 자주 잡히는지를 직접 결정한다. 너무 높으면 1번 케이스가 안 잡히고, 너무 낮으면 평범한 눌림까지 되돌림으로 오분류된다. **실데이터 백테스트에서 셋업별 성적표를 보고 조정할 것.**
- **사용자 경험칙의 통계적 검증** — 1번(과이격 되돌림)·2번(눌림목) 셋업이 실제로 손익분기를 넘는지는 아직 모른다. 화면의 셋업별 성적표가 그것을 재기 위해 만들어졌다. 셋업당 30건 미만이면 승률은 우연과 구분되지 않는다.
- **목표 R배수 기본값 1.38** — ADR-013이 ATR을 가격의 0.35%로 가정하고 뽑은 값인데, 실제 5분봉 ATR은 0.05~0.08%다. 그래서 현재 변동성에서 1.38R은 왕복 마찰조차 못 넘는다(증거금 대비 목표가 음수). 화면이 이제 그 상태를 빨간 경고로 잡아주고 최소 R배수를 알려주지만, **기본값 자체는 실데이터 백테스트로 정해야 한다.**
- **되돌림 셋업의 익절 방식** — 사용자는 실전에서 스택 하단까지 먹었지만, 엔진의 익절은 여전히 고정 1.38R이다. 화면에는 구조 목표가(스택 하단)를 참고로 띄우기만 한다. 어느 쪽이 나은지는 같은 구간을 두 설정으로 백테스트해 정해야 한다.

## 9. 다음 Phase 후보 (아직 설계 안 함)

`2-live`(소액 실거래)를 만든다면 전제 조건은 이렇다:
1. 백테스트 표본에서 손익분기를 유의하게 넘김
2. 페이퍼 괴리 검사 불일치 0건
3. 별도 어댑터로 주문 경로를 추가 — ADR-021의 모듈 경계를 의도적으로 넘는 결정이므로 새 ADR로 근거를 남길 것

**괴리 0은 "배선이 맞다"는 뜻이지 "엣지가 있다"는 뜻이 아니다.**
